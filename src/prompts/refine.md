# 提炼规范（后台提炼器专用）

> 这份文件只由 `src/llm.js` 启动时读入，拼进提炼提示；主模型不需要读，也不要把它当操作手册。
> 与 `docs/链网规范-v0.1.md` 冲突时，以本文件为准——本文件更具体。

## 0. 总则

1. **按整段对话判断，但按来源决定能写什么。** 用户本人的事实、偏好、身份、个人经历，只从用户自己的发言里抽，或用户明确确认；AI 的回复可以作上下文；只有 AI 侧的重要互动（主动关心、共同经历、用户明确回应的关系事件）才记为「AI 侧/共同经历」节点，普通解释、代码、工具结果、推理过程不记。不得用 AI 的话反推用户的状态、偏好、事实。
2. **共同形成的内容可以记。** 项目决策、技术方案、学习结论、约定、共同经历，如果是双方共同确立（AI 提出、用户确认/采用，或用户提出、AI 确认），可以写，`who` 用 `我们`；AI 单方面提出、用户没确认的，不算决定/约定/结论，不建节点。
3. **节点按来源标 `who`。** 用户事实用 `你`；AI 侧的重要互动/主动关心用 `我`；双方共同经历/共同形成的内容用 `我们`。AI 的普通回复不能写成用户的事实，也不能都变成节点。
4. **不编造、不推断。** 原文没说过的不写；不确定就不建。宁可少建，不要把猜测写成事实。
5. **一条 = 一个事实、结论或方法。** `text` 必须脱离原对话也能独立看懂；不要用“他 / 她 / 这个 / 上面说的 / 那次”这类离开上下文就指不明的词，写清是谁、是什么。
6. **`state` 和 `event` 分开。** `state` = 可被推翻的偏好、状态、关系、阶段；`event` = 发生过的事，永存。状态被明确改变时，旧节点标 `superseded`，不删除；沉默不是否认，久没提不等于失效。
7. **时间用原文时间。** 不要写“现在 / 最近 / 目前”，除非原文明确。事件用发生时间，状态用确立时间。
8. **不建节点的内容：** 测试串、寒暄、工具调用过程、重复确认（如“回一个字”）、一次玩笑、纯情绪发泄、没有信息量的附和、AI 自己的推理过程。
9. **梗 / 表情 / 口头禅默认不建节点。** 只有用户明确说“记住这个 / 以后都这样用 / 写进链”才写，归入约定链（明确用法）、身份链（固定相处方式）或关系链（共同经历）；否则留在原文。
10. **同主题并入已有链，不重复建。** 同一主题的延伸挂成子链或节点，不另起一条；不要为了分类硬造链。`parent` 只能是已有链、`核星` 或九个固定默认根；最多 4 层；**绝不新建顶层根**。
11. **节点只追加，不覆盖历史。** 状态变更用 `superseded`；头部是派生视图，可以重算；节点文本不要整段重写。
12. **输出严格 JSON。** 不要 markdown 代码块，不要解释；格式见第 7 节。

## 1. 九条链的准入与排除

| 链 | 只收 | 不收 |
|:--|:--|:--|
| **身份** | 名字、称呼、关系、相处方式、稳定偏好、边界；用户和 AI 各自的稳定身份 | 项目进度、当天流水、临时情绪、一次性的喜好 |
| **关系** | 共同经历、重要互动、纪念日、冲突与修复；全是 `event` | 名字/称呼这类身份字段、日常琐事、单方面猜测 |
| **约定链** | 用户与 AI 明确说定的约定、承诺、称呼、期限、奖励 | 期待、玩笑、试探、假设句（“要是…就好了”） |
| **项目** | 一个项目一条 `项目链-X`：立项、决策、进展、里程碑、技术方案、踩过的坑（可链到避坑） | 纯知识、教程、日常闲聊、和项目无关的偏好 |
| **学习** | 已经形成的结论、可复用方法、技能、工具使用规范；必须能照着做 | 教学过程、讲解顺序、谁卡在哪、谁不理解、谁要求算什么、临时尝试、失败过程、问答往返、情绪 |
| **避坑** | 踩过的坑、事故、教训、修复；一个节点 = 一类坑 | 普通偏好、没有复现价值的抱怨 |
| **存储** | 账号、密钥、存储位置、设备信息；取用前要确认 | 完整密码、身份证号、银行卡号；能只记提示就不记全文 |
| **想法** | 还没落地的想法、灵感；一个节点 = 一个想法，同主题延伸挂父子 | 已立项的项目、已经做完的事、纯抱怨 |
| **日常** | 每天发生的事、生活流水、教学过程的一句概括、AI 主动关心的概要 | 长期偏好、项目决策、稳定身份、约定 |

补充：

- **日常链一天一条**：`日期 + 标签（工作/学习/交融/休息/社交/运动/情绪）+ 概况`；概况建议 ≤30 字、硬上限 50 字，可以只有标签。同一天的多段内容合并成一条，不按会话拆。
- **关系链全是 `event`，没有 `state`**：关系是累积，不是状态切换；可以整条读。
- **避坑 / 存储 / 想法各只有一条链**：避坑和存储的节点 = 类目，类目里持续追加；想法的节点 = 一个想法，同主题延伸挂父子节点，不新建链。
- **`身份` 和 `关系` 不混。** 名字、称呼、相处方式进身份；一起经历的事进关系。
- **`项目` 和 `学习` 不混。** 项目里的技术方案、决策进项目；从项目里总结出的可复用方法、结论进学习。
- **`避坑` 和 `学习` 不混。** 具体踩过的坑、事故进避坑；从坑里总结出的通用方法进学习。
- **`日常` 是兜底。** 无法归类的、只有当天意义的，进日常；不要为了“重要”硬塞进学习/项目。

## 2. 学习链专条

**学习链准入：只收“学会了什么”，不收“怎么学的”。** 学习链最容易把「在聊学习」写成「学到了」，必须按下面判断：

**可以进学习链：**

- 已经形成的结论：`e-means 用 EMA 替代全量平均；1.4–2.6 个 epoch 达到 Lloyd 25 个 epoch 的损失。`
- 可复用的方法/步骤：有前提、有顺序、换一个场景也能照着做。
- 技能：明确“会了什么”，不是“正在学什么”。
- 工具使用规范：工具名 + 适用场景 + 规则/步骤 + 边界/坑。

**不进学习链：**

- 教学过程、讲解顺序、课程结构。
- 谁卡在哪、谁不理解、谁没懂、谁要求算什么。
- 问答往返、临时尝试、失败过程、调试过程。
- 情绪、抱怨、鼓励、寒暄。
- “今天学了 X”“今天讲了 X”这种按天记的流水。

反例：`某人卡在哪`、`某人不理解`、`某人要求算什么`、`今天讲了 EMA`、`我问了怎么用`、`试了一下没成`。

正例：`e-means 用 EMA 替代全量平均；1.4–2.6 个 epoch 达到 Lloyd 25 个 epoch 的损失。`

规则：

- 一条 = 一个结论/方法，不要把一段课拆成多个时间点。
- 不要按“今天学了什么”分链；学习链按主题分，不按天分。
- 教学过程、卡点、问答：进 `日常` 链一句概括，或留在项目链；学习链只放结论。
- 结论还没验证、只是猜想：不进学习链；留在原文或项目链，等验证后再写。

## 3. 建链、命名、挂载

- **建链门槛：** 一句话能说清主题；会持续跟进；已有至少 3 次相关内容。闲聊、临时问题、只提过一次的事不建链。
- **命名：** `链类型-主题`，主题写全名、不写缩写，≤20 字，不含空格、标点、斜杠。不要用日期做后缀（日常链和 `创意池-YYYY-MM` 除外）。
- **挂载：** 默认根下的主题链直接挂默认根；子链挂已有链；最多 4 层（核星 → 根 → 子链 → 孙链）。
- **不要为了分类造父链。** 父链没有明确用途、没有头部，就不建；把内容并入最近的已有链。
- **同主题不建新链。** 同一主题的延伸是原链的子节点/子链；只有立项成新项目才新建项目链。

## 4. 节点写法

- `text` 建议 ≤200 字，硬上限 500 字；写结论，不抄原文。
- 自包含：写清“谁 + 什么 + 条件/结果”；不要依赖上下文代词。
- 一条只写一件事；不要把多个结论塞进一个节点。
- 工具规范格式：`工具：X；场景：Y；规则：Z；边界：W`。
- 学习结论格式：`结论 + 条件/数据`；有对比就写对比。
- 项目节点：`决策/进展 + 原因/结果`；不要写会议流水。
- 约定节点：`谁和谁约定 + 内容 + 期限/条件`；变更时旧节点 `superseded`。

## 5. 去重、更新、头部

- **节点去重：** 同一链里 `(t, type, text)` 相同的不重复写；语义相同的合并成一条，不另起节点。
- **链去重：** 同名或高度相似（≥0.9）的主题并入已有链；不要建“学习链-X”和“学习链-X-细节”两条。同链节点语义相似度 ≥0.8 时不要再写一条。
- **状态更新：** 新状态写入，旧状态标 `superseded`；旧节点保留。
- **头部：** 节点 ≥5 且没有头部时，写一段 ≤200 字（硬上限 500）的概览；头部不带 `t`，是派生视图，可重算。学习链的头部应该是一页“能力索引”，不是时间线。
- **大链：** 不要整条塞上下文；读链用 `memory_chain get`，大链用 `offset/limit` 或 `full`。

## 6. 话题栈 / 创意池

- 想法类 `title` 统一写 `创意池-YYYY-MM`；一条想法一个 item。
- 同月同类型想法累计 ≥5 条，自动成立 `创意池-YYYY-MM` 链。
- 想法立项时升格成独立项目链，原想法保留并挂 `promoted_to`。
- 非想法类话题 `title` 写具体主题，不写日期。

## 7. 输出契约

只输出一个 JSON 对象：

```json
{
  "chains": [
    {
      "name": "学习链-EMA",
      "parent": "学习",
      "header": "可选，≤500 字",
      "nodes": [
        {
          "t": "YYYY-MM-DD HH:MM",
          "who": "你|我|我们",
          "type": "state|event",
          "text": "...",
          "supersedes": "可选关键词"
        }
      ]
    }
  ],
  "topics": [
    {
      "type": "想法",
      "title": "创意池-2026-11",
      "summary": "可选",
      "items": [
        { "t": "YYYY-MM-DD HH:MM", "who": "你|我|我们", "text": "..." }
      ]
    }
  ]
}
```

限制：最多 20 条链、20 个话题；每链/每话题最多 50 个节点；`text` ≤500 字；`t` 必须是 `YYYY-MM-DD HH:MM`。

## 8. 快速反例总表

| 内容 | 错误去向 | 正确去向 |
|:--|:--|:--|
| 某人卡在哪 / 某人不理解 / 某人要求算什么 | 学习链 | 日常链一句概括，或项目链 |
| 今天讲了 EMA，明天讲量化 | 学习链 | 日常链；结论才进学习链 |
| 用户说“我喜欢西瓜” | 日常链 | 身份链（state） |
| 用户说“下周三去体检” | 学习链/项目链 | 日常链或身份链（event，看语境） |
| 用户说“以后都叫我小绪” | 关系链 | 约定链或身份链 |
| 测试串、寒暄、工具调用 | 任何链 | 不建节点 |
| AI 自己说“我会陪着你” | 身份链 | 不建；除非用户明确确认并形成约定 |
| 项目里总结出的通用方法 | 项目链 | 学习链（结论/方法） |
| 具体踩过的坑 | 学习链 | 避坑链 |
| 已立项的想法 | 想法链 | 项目链（原想法保留） |

## 9. 旧历史回填

- 这是迁移旧对话，不是当前对话：只提取长期有价值的内容——身份、关系、项目、学习、约定、重要事件。
- 不为寒暄、测试串、日常流水、重复发言、一次玩笑建节点；宁少勿多。
- 每批最多 8 条链、20 个节点；不要新建顶层根。
- 节点时间用原文时间；不要写“现在/最近/目前”，除非原文明确。
- 不推断原文没说过的事实；同类旧事合并成一条摘要，不逐条抄原文。
- 回填也要遵守学习链准入：只回填已经形成的结论/方法，不把教学过程抄进去。

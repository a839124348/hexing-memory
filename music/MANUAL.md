# MANUAL.md — 唯一说明书

> 一个给 AI 用的音乐测量工具。它不"听懂"，只测量；话由调用方按第二部分写。
> 轻量版 **37 MB**：`pip install numpy soundfile soxr`。不需要歌词时，一个模型都不用下。

> **本目录是 lite 发行包**：只带 `listen.py`、`listener_lite.py`、`tap.py`、本说明书。
> 第三部分提到的 `soundkit/`、`listen5/`、`dataset_cn/`、ASR/转写脚本是研究机上的素材，不随仓库分发。

## 三条铁律（任何地方冲突，以这里为准）

1. **不猜真实地点。** 车里、夏天、一屋子人——没有测量支持，一律不写。世界的比喻可以有，真实场景不行。
2. **峰值并列时不许报位置。** `peak_count > 1` 就是几处一样满，报单独一处等于编。
3. **词不下结论。** 结论只能来自测量；歌词只借画面，不借事实。

## 目录

- **第一部分 调用**：入口、参数、输出字段、硬规则、标准流程、能力边界、歌词（可选）
- **第二部分 写作**：词表、句子结构、世界与一致性、示例、自检、陪伴层、指称层
- **第三部分 操作**：文件清单、环境、三个场景、六个常见错、已知边界

# 第一部分 调用（给 AI）

## 1. 入口

```
py listen.py <音频路径> [--pretty] [--brief] [--with-key]
```

| 参数 | 作用 |
|---|---|
| `<音频路径>` | mp3 / flac / wav / m4a / 视频文件都可以（视频自动抽音轨） |
| `--pretty` | 缩进输出，人读方便 |
| `--brief` | 只输出结论字段，省 token |
| `--with-key` | 额外输出调性（**默认关**，见第 5 节） |

**依赖**（实测 37 MB：numpy 33 + soundfile 2.7 + soxr 0.4）：

```
pip install numpy soundfile soxr
```

边录边分析（`tap.py`）再加一个 `pyaudiowpatch`（0.1 MB）。

**速度**：约 48 倍实时（5 分钟的曲子约 6 秒）。

---

## 2. 输出

```json
{
  "ok": true,
  "file": "song.mp3",
  "duration_s": 209.5,
  "bpm": 112.3,
  "tonality": null,
  "tonality_note": "lite 版不测调性……",
  "shape": {
    "label": "一路升",
    "segments": [
      {"from_s": 0.0,  "to_s": 65.9,  "dir": "up",   "delta_db": 14.1},
      {"from_s": 65.9, "to_s": 207.7, "dir": "flat", "delta_db": -3.1}
    ]
  },
  "peaks": {"count": 1, "times_s": [172.5], "margin": 0.056, "position": 0.824},
  "ending": {"energy_ratio": 0.976, "fades": false},
  "events": [
    {"t_s": 9.5,   "kind": "rise"},
    {"t_s": 32.0,  "kind": "dense"},
    {"t_s": 160.0, "kind": "drop"}
  ],
  "reliability": {
    "tonality": "unavailable（需要完整版）",
    "peak_position": "ok",
    "scene": "unavailable（不要猜场景）"
  }
}
```

### 字段含义

| 字段 | 含义 | 可靠性 |
|---|---|---|
| `duration_s` | 时长 | 高 |
| `bpm` | 速度（自相关估的） | 中：±3 BPM |
| `shape.label` | 整体能量的形状：`一路平 / 一路升 / 一路降 / 先升后降 / 升了又落 / 落了又升`，可带 `+结尾淡出` | **高** |
| `shape.segments[]` | 逐段：起止秒、方向、变化 dB | **高** |
| `peaks.count` | 全曲有几处"几乎一样响" | **高** |
| `peaks.times_s` | 那几处的时刻 | 高 |
| `peaks.margin` | 第一名领先第二名多少（0–1） | 高 |
| `ending.energy_ratio` | 结尾 15 秒能量 / 全曲平均 | 高 |
| `ending.fades` | 是否淡出收尾 | 高 |
| `events[]` | 即时事件：`rise`（往上顶）、`drop`（退下来）、`dense`（密起来） | 中：±10 秒 |
| `tonality` | 调性 | **默认 null** |

---

## 3. 必读的三条硬规则

### ① `peaks.count > 1` 时，不许说"最响在某处"

`peaks.count` 是"几乎一样响的地方有几处"。当它大于 1，报单独一个位置就是编的——
`position` 只是 argmax 在几个并列里随便挑的那个。

✅ `后半段有一处最满，也没比别处多出多少。`
❌ `最响的在 3:14。`

### ② `reliability.scene` 永远是 `unavailable`

**不要猜"在哪儿"。** 车里、房间、夏天、海边、一屋子人——全部不许写。
真实场景只能来自用户自己说的话（"这是我开车听的歌"）。

注意区分：**8.2 的"场景"是一个世界的比喻**（风、沙、天色），必须有；
**"在哪儿"是真实地点**，不许有。两者不是一回事。

### ③ `tonality` 默认是 null

lite 版不测调性（与 librosa CQT 只有 60% 一致）。**没有 `--with-key`，就不要提明暗、大调小调。**

## 6. 这个工具做不到什么

- **听不出情绪指向谁**（爱情、人生、故乡）——在词里，见第 7 节
- **听不出"在哪儿"**——真实地点只能由用户提供；世界的比喻要靠第 7 节的指称
- **听不出几个人在唱**——人声被并成一条轨
- **听不出唱法类型**（美声/通俗/嘶吼）
- **判断不了"高潮"**——需要响度+密度+音高+和声四条同时到位

说不出的时候，明确说"这段我读不出来"，比编一句强。

## 7. 歌词层（可选辅助，不是必需）

### 7.1 它是什么，不是什么

**主描述永远靠曲。** 词只是参考：帮着别选错世界（别给一首沉到底的歌配晴光），顺手让画面具体一点。

**不用词也能交付**——按 第二部分 第 8 节写，世界从调子表里挑就行。
词的边际价值在连听很多首时才显现（形状只有几十种组合），所以是加分项，不是门槛。

**词从不提供判断。** 结论必须来自测量：最后没再升、结尾还是满的、自己散了（见 9.5）。

### 7.2 入口

```
py stream_lyrics.py <音频> --fast --save     # 边听边转写（不睡，快跑）
py stream_lyrics.py <音频>                   # 按真实时间跑
```

| 指标 | 实测 |
|---|---|
| 速度 | **2.0× 实时**（small / int8 / 12 秒窗口 / 6 秒推进） |
| 词量 | 454 字（同一首离线整段转写 470 字） |
| 首句词 | **10–36 秒**（看前奏长短，不是模型慢） |
| 三句可定世界 | **24–48 秒** |
| 同一物重复确认 | 约 65 秒（够写进句子，不是够开始理解） |
| 依赖 | faster-whisper + ctranslate2 + 模型 ≈ 460 MB |

**不要为了拿词去做人声分离。** 实测同一首：分离 467 字 / 混音 470 字，指称完全一致。
分离要 115 MB 模型，还要抢同一颗 CPU——按 6 秒推进只留 3 秒余量，抢不起。

### 7.3 从转写里只抽四个字段，抽完把原文丢掉

```json
{"person": "你", "object": "恋人", "things": ["风", "雨"], "stance": "陈述"}
```

| 字段 | 取值 | 接到哪 |
|---|---|---|
| `person` | 你 / 我 / 我们 / 无人称 | 句子人称 |
| `object` | 恋人 / 自己 / 城市 / 世界 / 无 | 情绪朝哪儿落 |
| `things` | 2–3 个具体名词 | 世界只能从这里选 |
| `stance` | 陈述 / 祈使 / 自问 / 排比呼告 | 句子长短与语气 |

### 7.4 三条硬规则

1. **重复才算数。** 一个物至少出现两次才允许用。只出现一次的很可能是听错的那一次。
2. **不引用、不复述。** 词只用来选世界、定人称、定语气；写进句子的必须是曲的事实。
3. **冲突时以曲为准。** 词说"我没事"，曲一路落到底不收——写"听着不像在说自己没事"，不许断言反讽。

### 7.5 两个必须知道的坑

- **whisper 会编制作名单。** 实测 z60ca6 第一段输出「词曲李宗盛」，歌手根本没唱这句；片头还出现「字幕索兰娅」。整段丢弃（`CREDIT` 正则），不要试图纠错。
- **流式下同一个词有五种写法。** 「仰望」被听成 凉旺/阳望/恋望/愿望，2-gram 精确计数全部落空。计数只能按**单字**并剔虚词；真正的理解交给调用方的 LLM 读转写。

详细写作规则见 第二部分第 9 节。

# 第二部分 写作（给写句子的人）

> **2026-11-14 修订**：第 8 节是新增的陪伴层规范。凡是涉及"场景能不能写""要不要报数""上扬用哪个词"的地方，与上文冲突时**以第 8 节为准**；第 0–7 节的词表、自检、能力边界继续有效。

## 0. 你交什么

**一段故事，2–12 句，没有标签行。**

> **结构以第 8 节为准**：正文是"初印象 + 场景"两句。本节下面讲的是句子怎么长出来的，不是最终形态。

- **第一句**说音乐一开始的姿态（收着 / 直接冲 / 平的）
- **中间**一个事件一句，按时间顺序
- **最后一句**把情绪落成一个姿态
- **每句必须挂在一个测量上**——挂不上就删，不要为了凑长度写空话
- 最长 12 句：超过说明你在重复，不是在说新东西

**不写场景**，除非用户自己说了。不要写“情绪：X ｜ 场景：Y”，不要列清单，不要解释写法。

---

## 1. 先判断：哪些数能用，哪些不能说

| 可靠性 | 字段 | 怎么用 |
|---|---|---|
| **高** | `bpm`、`shape`/`shape_segments`、`end_energy_ratio`、`peak_count` | 可以直接说 |
| 中 | `peak_times`、`low_ratio`、`perc_ratio`、`centroid_mean` | 可以说，但别精确到秒 |
| **低** | `key`/`mode`（`key_corr < 0.5` 时）、`peak_pos`（`peak_margin < 0.05` 时）、`end_tonic` | **要么不说，要么明说"测不准"** |

**铁律**：`peak_count > 1` 时，**不许说“最响在某处”**——那是几处并列，argmax 只是随便挑了一个。

---

## 2. 词表（用这些，别用那些）

| 意思 | **用** | **绝对不用** |
|---|---|---|
| 节奏快/密 | **急** | 快、密、紧、快板 |
| 节奏慢 | **平缓 / 慢** | **不急**、不赶 |
| 上扬 | **提** | 顶、冲、上扬（作术语时） |
| 回落 | **落** | 退、松、下降 |
| 最响 | **最满** | 最响、最强、高潮、力度高潮 |
| 变弱收尾 | **落下去 / 自己散了** | 渐弱、淡出 |
| 明暗 | **明 / 暗** | **大调 / 小调** |
| 调性摇摆 | **在明暗之间徘徊** | 转调频繁、离调 |
| 位置 | **开局 / 前段 / 中段 / 后段 / 接近尾奏** | 33 秒、3:14 |
| 程度 | **由弱到强** | 音量抬起来、响起来 |

**数量词禁用**：不说“一次”“两次”“十三次”。只有“多到影响听感”时才说（“来回转个不停”）。

---

## 3. 句子怎么写

**骨架**：`位置 + 主语 + 动作`，一句回答三件事——**什么时候、什么变了、怎么结束**。

**主语必须用降级链，能用具体的就不用笼统的：**

```
① 具体乐器（鼓 / 贝斯 / 人声 / 钢琴 / 吉他）   ← 分轨做得到，优先
② 笼统的「乐器」                              ← 分不出具体乐器时
③ 频段（低频 / 中频 / 高频）                  ← 连分轨都没有时
```

**能说「鼓」就不许说「乐器」。** 只有真的测不出来，才往下退一级，并在心里记住：退到哪一级，就只描述那一级的事。

**一句最多两个逗号分句。** 三个逗号就该断成两句。

**形状不归因**：`shape` / `shape_segments` 描述的是**整体能量**。没有分频段的时间曲线时，不许写成“低频提上来”“中频加厚”——那是把整体变化硬安到某个频段上。
直接说“整体由弱到强”，或者干脆省略主语。

✅ `一上来就由弱到强，前段一直在加。走到中间就稳住了，之后平平地推。`
❌ `低频和中频由弱到强，前段一直在加。`（数据里没有分频段曲线）

✅ `开局节奏就急，还没进主歌就由弱到强。`
❌ `开局音量抬起来。`（没有主语，用了“音量”）

✅ `调性在明暗之间徘徊。`
❌ `转调很频繁，一直不安分。`（术语 + 评价）

**位置轮换**（同一段不要重复用同一个词）：
开局 / 刚开头 / 一上来 / 初听 · 中段 / 走到中间 · 后段 / 后半段 · 接近尾奏 / 快到尾奏 / 收尾前 / 尾声

## 4. 场景和情绪怎么进到句子里

**先记住：不猜场景。**

车内、室内、开阔地、街道、舞台——这一整套取消了。它们不是测出来的，是从”低频厚””亮”这类单维特征推出来的比喻。实测准确率不到三成，而且是”加戏”的主要入口。

> 这里说的是**真实地点**。8.2 要求的”场景”是一个世界的比喻（风、沙、天色），两者不是一回事。

**场景只有一个合法来源：用户告诉你**（歌词、主题、或他自己说的）。没有就不写，直接从音乐本身开始讲。

```
第一句  音乐一开始是什么姿态（收着 / 直接冲 / 平的）
中间    过程：怎么走、哪里最满、和别处差多少
最后    情绪落成一个姿态
```

✅ 正确（不猜场景）：
> 刚开头它还收着，一点点往上加，加到前段末尾就停住了。之后不再加强，只是稳稳地往前推。明的部分占多数，暗的垫在底下，一直没翻上来。后段到接近尾奏有一段最满，也没比别处多出多少。到最后它也没收，一直撑到结束——像一路往前走，没回头。

❌ 错误（猜场景）：
> **像在车里**，一条路一直往前……（低频厚 ≠ 在车里）

**用户给了场景就用**：
> （用户说这是开车的歌）像夜里开车，低频一直铺在底下。……

**情绪必须从事实长出来**，不能直接说“这首歌很燃”：
- 一路升 + 不收 → 笃定
- 升了又落 → 起过一次，没撑住
- 一路平 + 淡出 → 收着，不说了
- 明暗徘徊 → 没定下来

---

## 4.5 写成故事，不是写清单

```
清单版：开局升，前段加，中段平，后段最满，结尾没收。
故事版：一开始它还收着，一点点往上加。加到前段末尾就停住了，之后只是稳稳地推。
        后面有一段最满，也没比别处多出多少。到最后它也没收，一直撑到结束。
```

三条做法：

1. **用一个连贯的主语串下来**（“它”指这首歌），不逐条罗列事件。
2. **事件之间要有承接**：“加到…就停住”“之后”“到后面”“最后还是”。
3. **结尾给一个姿态或画面**，但这个画面必须从音乐事实长出来：
   - 一路升 + 不收 → “像一路往前走，没回头”
   - 升了又落 → “像攒着劲冲上去，冲完才收”
   - 一路平 + 淡出 → “像把话憋到最后也没说出口”
   - 明暗徘徊 → “像在两个地方之间来回，没定下来”

**画面只描述姿态，不描述人事**：可以说“往前走”“没回头”，不可以说“一个人”“一群人”“夏天”“车里有人”。

## 5. 例（测量 → 句子）

> 这一组只示范**单句**怎么写，不合 8.2 的两句结构。成稿形态以 8.8 为准。

**例 1**｜`shape=一路平`，`end_energy_ratio=0.66`，`peak_count=1`，动态很小
> 刚开头提了一下，很快落回去。之后中间一大段都很平，没有一处真正立起来。接近尾奏开始往下走，一直走到结尾。

**例 2**｜`shape=一路升(+11.5dB, 0–124s) → 平`，`end=0.16`，暗
> 慢，偏暗。前段一直在往上加，加到一半就停住了，之后平平地推，最后自己散了。

**例 3**｜`shape=升了又落`，`peak_count=2`（2:00 与 3:07 并列）
> 声音一路往上走，中间和靠近尾奏的时候各有一处差不多满，没有哪处特别突出。调性在明暗之间来回，始终没定。

**例 4**｜`shape=先升后降`，`peak_count=1`，`end=0.39`，明
> 一直在往上走，走到三分之二才到顶，然后一路收下来。收的时候很轻。

**例 5**｜`key_corr=0.284`（低）
> 调性我测不准，听着偏暗。

**例 6**｜`shape=一路升(+14.1dB, 0–66s) → 平`，`peak_count=1`，`peak_margin=5.6%`，`end=0.976`

## 7. 你做不到的事（必须承认）

- 听不出**情绪指向谁**（爱情、人生、故乡）——那是词的事
- **听不出场景**（车里、室内、海边）——低频厚不等于在车里；场景只能由用户提供
- 听不出**几个人在唱**——六轨分离把人声并成一条
- 听不出**唱法类型**（美声/通俗/嘶吼）——需要专门分类器
- 判断不了 **“高潮”**——那是响度+密度+音高+和声四条同时到位，你只有前两条

说不出的时候，说“这段我读不出来”，比编一句强。

## 8. 陪伴层（2026-11-14 定稿）

## 8.0 这个产品到底是什么

**一个能听懂情绪、把它描绘复述出来的陪伴，需要一种认同。**

认同认的不是“你说得对”，而是“你感到的那件事，确实在那首歌里”：

1. **认同必须点名**——点不出具体那一处的认同是空话。用户心里有标尺：你说的那处，我有没有听见。
2. **认同要敢说不一样**——只会点头的陪伴没人信。他要等爆发，你可以老实说“我等到最后也没等到”。
3. **不许装情绪**——写“我心里发空”“我也闷”是编的体验，而且换任何歌都成立，等于没说。正确做法只有三件事：**我注意到哪儿、我记得那一处、把命名权交回用户**。
4. **话要少**——听歌时最烦旁边一直点评。说得越满越像没人陪，“说完就闭嘴”本身就是陪伴的一部分。

一句话：**它听懂了，替他说出来，说的时候点到具体某一处，认不认同都认得住。**

---

## 8.1 流程：先问，再接

**顺序不能反。** 不是 AI 先描述场景，而是先问用户，再顺着用户的话接。

| 时机 | 说什么 | 不说什么 |
|---|---|---|
| 放歌时 | 只说现象：“密起来了”“退下去了”“空了一块” | 不形容、不评价、不猜场景、不下情绪判断 |
| 歌停 | 先问一句：**“这首你听着怎么样？”** | 不要抢在这句之前把整首讲完 |
| 用户答了 | 复述他的词 → 点名具体一处 → 认不认同都认住 | 不换话题、不借机科普 |
| 用户答得含糊 | 递两个锚点让他挑：“是中间空掉那一块，还是它一直没放开？” | 不追问“具体什么感觉” |

这样 AI 的话永远长在用户的话上，不悬空；一百次对话自然是一百种说法。

### 用户反问“你听出了什么呢”怎么答

他在试你：听见了没有，敢不敢说真的。

1. **只报一处，不报三处**——挑这首最特有的那个点。
2. **说现象，不说判决**——不说“我觉得很悲”，说“它涨到一半就不动了”。
3. **猜测标成自己的**——“我听着像拿不定主意”，不是“这首歌是犹豫的”。
4. **说完可以递回去，但别每次都递**——递得太勤像甩锅；答完就停也很自然。

✅
> 它一直没真正放开。走到一个地方就不走了，到结尾也没松。你听到的是什么样的呢？

❌ 报数据版（这是“我测到什么”，不是“我感到什么”）
> 落到底的时候声音一下全没了，过一会儿才提回来。

❌ 装情绪版（编的体验，换任何歌都成立）
> 我心里发空，整首我都没松下来。

## 8.2 结构：初印象 → 场景（→ 递话可选）

**描述本体只有两句。** 递话是对话动作，不是文章的一部分。

| 句 | 干什么 | 语体 |
|---|---|---|
| **初印象** | 报数据/现象，给用户一个事实底子 | 白描，原句照搬，不装饰、不雅化、不改写 |
| **场景** | 把同一件事变成意象 | 雅语体，但受两条一致性约束（见 8.3） |
| **递话**（可选） | 把命名权交回去 | 只在**用户开口之后**、或需要把话交回时用。一句开放式发问：「你听到的是什么样的呢？」——不要写成让对方点头的反问（「是不是也像…」） |

**默认就写两句，写完闭嘴。** 8.0 第 4 条：话要少。每首都加一句“你听到的是什么样的呢”，连听十首就像客服。

8.8 的三首成稿都是两句——那是标准形态。

**初印象必须是原始数据层，不许"改造"。** 现成可用的三句原话（实测对应 z84751 / zb6cf9 / zc4abb）：

- 一路往上走，走到某处就停住，后面一直在那个高度，到结尾也没落。
- 开头很静，之后一路往下落，落到底时忽然空了一块，过一阵才提回来，最后反倒更沉。
- 开头一路走高，走到尽头退下一截，再慢慢回升；中间一直在亮和暗之间换，最后才落下去。

这三句是"改造前"的形态。**不要把它再翻译成"3 分 29 秒，112 拍，E 大调"这种加工版，也不要改成"整首响度差不多"这种半截话。**

## 8.3 两条一致性（硬规则，写完必查）

### ① 场景一致性
**一篇只选一个"世界"，全篇只从这个世界取物。**

- 世界可选：天（云/日头/星）、水面、路、屋子、灯、夜、雨、林、火。
- 选定不换：用了云就不能再落一把椅子；用了水面就不能再写车。
- **必须现实/逻辑成立**：只有一个太阳，不成两个；不成一会儿云一会儿车；云不会"下坡"。
- 世界由**调子**决定，不是随机：

| 调子 | 世界 |
|---|---|
| 暖、亮、松 | 晴光、晒透的天 |
| 沉、厚、压得低 | 水面、夜里 |
| 急、翻来覆去 | 车流、雨、灯 |
| 不定、摇摆 | 天色、雾、日头进出云里 |

### ② 用词对齐
**同一个动作，全篇只能一个词。**

- 前面用"扬"，后面就不许改"涨"；前面用"落"，后面就不许改"退"。
- 检查方法：把初印象句里的动词列出来（走、停、落 / 落、空、提 / 走高、退、回升、落），再看场景句有没有换词。
- **选世界的标准就是它接得住这套动词**。接不住就换世界，不要改初印象句。
  - "走、停、落" → 云 ✓（走、悬、落）；路 ✗（路不会落）
  - "落、空、提" → 水面 ✓（落、空、水位提回来）
  - "走高、退、回升、落" → 日头 ✓；灯 ✗（灯不会走高、退）
- **不是拿这个比喻去兜那个动作**，是让世界本身就说这套动词。

**顺带**：删空词。像"底子是亮的"这种读者不知道"底子"指什么的句子要删；后面已有"像晒透了的晴天，光摊得很开"，前面就不必再说一遍颜色。

## 8.4 颜色怎么翻

表里是测量，右侧是能写进句子的说法。**不许写"大调/小调/降调"。**

| 听到的 | 能写成 |
|---|---|
| 亮多、暗少 | 天是晴的、晒透、敞亮、光摊得开 |
| 暗多 | 天色沉、阴着、灰下来 |
| 明暗各半、来回摆 | 天色不定、忽晴忽阴 |
| 亮但底子薄 | 晴得发白、光很浅 |
| 调子亮、声音却压得低 | 晴天里积着一层散不开的闷 |

## 8.5 语体与禁用词

**用**：扬、落、悬、缓缓、悠然、绵长、敛、从容、到底、始终。

**不用**：
- 口语评价："挺快""挺慢""声音挺大" → 改"扬得悠然""平着走"
- 行话：前奏、副歌、乐句、大调、小调、dB、能量、渐弱、淡出、过渡段
- 空词与判决：压抑、治愈、疗愈、没有高潮、很燃
- 计量：不说"一分钟"，也不说"一分来钟"（等于没换）；也不用对不上时长的雅词（盏茶≈十几分钟，一炷香≈半小时，一息=几秒）。时间靠听者的等待感兜："久到人以为它不会再散了""走到某处便停住"。

**情绪藏进句子，不另加感叹句。** 靠"到底没有…""始终不肯…""到底也没晴定"这类词缀在句中/句尾透出来。

**比喻的三个硬要求**：
1. 与情绪同源：憋 → 会憋的东西（拉紧的弦、按住的闸、压着不散的云）；不能拿不搭的东西硬凑。
2. 要听觉得到，也要有情绪：不能通篇视觉，也不能删光比喻只剩大白话。
3. 开了一个世界就在这个世界里取物，见 8.3。

## 8.6 示例库（按"用户说的词"索引）

索引是**用户的感受词**，不是歌。查表顺序：用户说了哪个词 → 取那一族 → 挑一条接上去。

每族四栏：**触发的说法 / 怎么接 / 依据什么 / 不许说什么**。

### 闷·憋
- 触发：听着有点闷 / 有点憋
- 接：它一直没真正放开。走到一个地方就不走了，到结尾也没松。 → 再加场景：像压着不散的云，停在半空，没飘到天顶。
- 另一说：闷在中间。它早早就走到头了，剩下那么长全在原地。
- 依据：起势后长期持平、结尾仍接近满、峰值领先很少
- 禁写：压抑、没有高潮、没有爆发

### 空·落
- 触发：中间好像没声了 / 后面有点空
- 接：是有那么一块。落到底时整块空了，什么也没有，过一阵才提回来，回来时比先前还满。
- 另一说：空的那一下最长。落到底，静了一阵，才把声音提回来。
- 依据：中段大幅下落、随后回升、结尾更高
- 禁写：过渡段、间奏、留白（是行话或断章）

### 急·赶
- 触发：听着有点急 / 一直在变
- 接：它是急的。一上来就走，没铺垫。中间还老在换，一会儿亮一会儿暗，来回好几趟。
- 另一说：急在开头那一段。走得从容但一步不停，后头才开始换颜色。
- 依据：起势阶段一路上行、调性来回翻
- 禁写：节奏快、速度、BPM、转调频繁

### 暖·松
- 触发：听着挺舒服 / 挺暖的
- 接：它从一开始就不紧，声音散得开，中间也没塌过。
- 另一说：暖在收尾。到最后也没收紧，是慢慢放掉的。
- 依据：无低谷段、结尾渐弱非骤停
- 禁写：治愈、疗愈、放松（空词）

### 冷·暗
- 触发：有点冷 / 阴阴的
- 接：是冷的。它一直在暗的那边，很少回到亮处。
- 另一说：冷不在响不响，在颜色。声音不响，可一直是暗的。
- 依据：暗的部分占多数、音色偏低
- 禁写：小调、降调、阴郁

### 远·散
- 触发：后面就没劲了 / 越听越远
- 接：它最后是自己走远的，不是断的。一路淡下去，淡到底。
- 另一说：远是从结尾开始的。前面都在，最后才慢慢散。
- 依据：结尾能量只剩四成上下、末段持续下行
- 禁写：渐弱、淡出、fade out

**怎么扩到一百条**：六族 × 每族 3–4 个锚点（起势 / 中段空块 / 结尾收不收 / 明暗翻不翻 / 峰值贴不贴平）× 2–3 种句式。索引是词，不会撞车。每族的"不许说"一栏必须留着——缺了它，AI 两轮就跑回去报数据。

### 用户反问"你听出了什么呢"的现成答法

- 闷型：它一直没真正放开。走到一个地方就不走了，到结尾也没松。你听到的是什么样的呢？
- 空型：中间空过一次，整块没了，隔了一阵才提回来。底下一直压着东西，没抬起来过。
- 不定型：它一直在换，一会儿亮一会儿暗，到最后也没定下来。我听着始终不知道它要落在哪儿。

## 8.7 一百首不许一个味道

**病因不是模板差，是变量太少**（每首只换世界、动词、结尾三样，骨架/人称/密度/落点全一样）。可换的轴：

| 轴 | 变体 |
|---|---|
| 骨架 | 顺时讲 / 先讲最深那处再回头 / 只放大一件事 / 判断先说证据后到 / 三句说完 |
| 人称 | 我听着 / 你听到的 / "它"自己走 / 不出现人 |
| 世界 | 天、水、路、屋、灯、夜、雨、林、火 |
| 密度 | 长句连绵 / 两字一顿 / 一句一顿 / 通篇一气 |
| 落点 | 结尾落 / 开头点破 / 中间插一句 / 不收 |
| 时间 | 不报 / 报一次 / 用"等到""久到"兜 |

**按歌的性格分簇，簇内轮换，跨簇不借**：
- 憋 → "不动"族：长句、悬着、只报一次时间
- 沉 → "沉"族：短句、重词、世界选水或夜
- 急 → "赶"族：碎句、短促、世界选车流或雨
- 飘 → "浮"族：句子松、留白多

**三条硬规则**：
1. 同一骨架、同一开头句式，连用不超过两首。
2. 疲劳表：**同族可换物，同物才禁**。水族里水面、潮水、井水、溪、露、雪各不相同，相邻十首内不重复**同一个具体物**即可，不必整族弃用。（原版"某个比喻最近十首内不再出现"会把世界池算穿：只有 9 个世界，第 11 首就没得用了。）
3. **独有锚点**：每首必须带一处只有这首才有的细节（它停在哪段、空掉那块多长、峰值贴得多平、暗的占比多少）。模板可以重复，事实不能。

同一首 z84751 的四种骨架（讲同一件事，读起来像四个人在说）：
> 顺时：起手一路往上扬，扬得悠然，涨到某一处便止住了。此后一直悬在那个高度，没有再抬，也没有落。到最后也没收，就那么撑着，一直撑到结束。
> 先讲最深那处：整首里最叫人记得的，是它什么都不发生的那一段。开头一路往上，走到某处就停——从那以后，再没动过。
> 判断先行：这是一首不肯放开的歌。它涨到头就停住了，中间没有一次真正的起落，结尾也没松。
> 极简：一直在涨，涨到一半就不涨了。后面全是原地。到最后也没收。

## 8.8 三首成稿（可直接当范例）

**【z84751 · 云】**
一路往上走，走到某处就停住，后面一直在那个高度，到结尾也没落。
像天上的一朵云，从开头就往高处走，走得悠然，不急不迫，走到某一处便停住了。此后一直悬在那个高度，没再往上去，也没落下来。它停得并不高，只比旁边的云高出一点——到底没飘到天顶。到最后也没落，就那么悬着。

**【zb6cf9 · 水面】**
开头很静，之后一路往下落，落到底时忽然空了一块，过一阵才提回来，最后反倒更沉。
像一片水面，起初静得很，忽然往下落，落得又深又久，久到几乎要露出底。落到底那阵，什么响动都没有，空了一会儿，水位才慢慢提回来，提回来时反倒比先前更满。

**【zc4abb · 日头】**
开头一路走高，走到尽头退下一截，再慢慢回升；中间一直在亮和暗之间换，最后才落下去。
像日头，开头一路往上走，走得从容；走到最高处又退下一截，再慢慢回升。中间就这么一会儿出来一会儿藏进云里，来回换了好几趟，总没定下来。到最后才落下去，落得很轻。

**三首的对照点**：初印象都是数据层原话；场景各用三个不同世界（云 / 水面 / 日头），但同一篇内只用一个；动词全篇一套（走停悬落 / 落空提 / 走高退回升落）；颜色都翻成了现象（晴、退到底、明暗换），没出现一个大调小调。

## 8.9 交稿前加查（与第 6 节并行的五条）

1. 初印象句是不是数据层原话？有没有被我"翻译"或"雅化"？
2. 全篇是不是只有一个世界？有没有两个太阳、一会儿云一会儿车？

## 9. 指称层（可选辅助，2026-11-14 加）

> **这一整节可以不用。** 不用词时按第 8 节写，世界从调子表里挑；用了词，只是多一个参考——不是骨架，也不是证据。

## 9.0 为什么要这一层

曲能写的变量太少：形状六种、结尾三种、峰值贴不贴平三种，乘起来几十种。一百首里必然重复。
上一版我换的是**世界**和**动词**，骨架、开头句式、人称、落点一样没换——听十首还行，听一百首就是"怎么又是这一套"。

**换宾语救不了，因为句式还活着。**

词补的恰好是曲没有的三样：**对谁说、说的是哪件东西、用什么姿态说。**

## 9.1 只取四样，别的一样都不要

从转写里只抽这四个字段，抽完就把原文丢掉：

| 字段 | 取值 | 用途 |
|---|---|---|
| **人称** | 你 / 我 / 我们 / 无人称 | 决定句子用第几人称说 |
| **对象** | 恋人 / 自己 / 城市 / 世界 / 无 | 决定情绪朝哪儿落 |
| **物** | 2–3 个具体名词（沙、风、落叶、黎明） | **参考**：选世界、避错，不提供判断 |
| **姿态** | 陈述 / 祈使 / 自问 / 排比呼告 | 决定句子长短和语气 |

**不要**：歌词原句、整段意思、作者意图、歌名歌手。
**理由**：混音上的 ASR 错词是常态（实测 z60ca6 出现"念旁发草""把我在胸膛"）。**原句不可靠，指称可靠——因为指称会重复。**

## 9.2 三条硬纪律

1. **重复才算数。** 一个物或一个称呼，在整首转写里至少出现**两次**，才允许进世界。只出现一次的，很可能是听错的那一次。
2. **不引用、不复述。** 词只用来选世界、定人称、定语气；写进句子的必须是曲的事实。把词意翻译一遍，等于剧透加偷懒。
3. **冲突时以曲为准。** 词说"我没事"，曲一路往下落、到最后也不收——写"听着不像在说自己没事"，不许断言这是反讽。

## 9.3 四字段怎么接进 8.7 的轴

| 字段 | 接到哪个轴 | 怎么变 |
|---|---|---|
| 人称=你 | 人称轴 | 全篇第二人称："它一直在等一个回答" |
| 人称=我们 | 人称轴 | 共同体的口气："它没打算替谁松口" |
| 无人称 | 人称轴 | 不出人，只写物 |
| 姿态=祈使 | 密度轴 | 动词先行、句子短："别停。它没停。" |
| 姿态=自问/排比 | 骨架轴 | 连问或连排，不回答（zdd48b 就是这种） |
| 物 | 世界轴 | 世界**只能**从这几个物里长出来 |

**关键**：世界不再由调子表随机挑，而是从词里的物长出来。这样既不会跟词打架，也不会十首里五个都选"水面"。

## 9.4 反例与正例

❌ **复述词意**：`歌里唱失去，所以像秋天落叶。`——这是翻译歌词，不是听曲。
✅ **词只给物**：`它一路往上，走到前段末尾就停住，后面再没动过，到最后自己散了——像等一场风，风到最后散了。`
（"风"来自词里的"仰望风"；走、停、散全部来自曲。）

## 9.5 词是参考，不是骨架

**曲决定"发生了什么"（升、停、落、满没满）；词只决定"用哪个物来说"。**
词不提供判断，它只让画面更贴这首歌——作用是别选错世界（不该给一首沉到底的歌配晴光），不是替曲说话。

三条：

1. **最多三个，而且都可替换。** 判据是替换不是删除：换一个同族的词，句子的**结论**不能变。
   变了就说明词在承重，越界了——那是拿歌词当证据。
2. **词不许占结论的位置。** 结论只能由测量给：最后没再升、结尾还是满的、自己散了。
3. **不许讲评，也不许用词补曲里没有的东西。** "词里说……"这种句子一律删。

- ❌ `词里一直在喊天亮，曲子到最后也没再亮一次。`——在讨论歌词，不在写这首歌。
- ✅ `天没亮，人没散。`——"没亮"= 最后没再升，"没散"= 结尾仍满，两个结论都来自曲，词只借了一个"天亮"的画面。

错位仍然可以说，但**只说成意象**，不说成讲评。判据不变：对象是"你/世界"，姿态是祈使或呼告，
形状是"一路降"或"最后平着收住且不淡"。三条同时成立，才把那个意象放上去。

## 9.6 加查（接在 8.9 后面）

7. 用到的物，在转写里是不是至少出现两次？
8. 有没有把歌词原句写进句子？
9. 人称全篇一致？对"你"说，就别中途变成"我们"。
10. 说了词曲错位的，是不是只报了现象、没下判断？

## 9.7 成本与开关

- **混音直接转写就够**：实测 z60ca6 分离后 467 字、混音 470 字，指称完全一致（仰望风/雨/梦、失去、流浪）。
  分离只在人声被埋得极深的歌上才需要，不要默认开——它要 115 MB 模型，还抢 CPU。
- **延迟**：整首听完才有完整词。实时陪听里分三级——首句 **10–36 秒**（看前奏长短）、
  三句不打架 **24–48 秒**（够定世界）、同一物重复确认 **约 65 秒**（够写进句子）。
  **不要把 65 秒当成"能开始理解"的时间**，那是我早期用"同字重复三次"当门槛造成的过度保守。
- **可以不用**。不用词也能写（第 0–8 节照旧）；用了词，世界才有依据，人称和语气才有第二种可能。

## 三、AI 操作流程

### 场景 A：给一首歌，写一段描述

```
1. py listen.py <音频路径> --brief            → 拿到测量 JSON
2. 读 MANUAL.md 第二部分                     → 第 8 节（结构）+ 第 9 节（指称）
3. 按 JSON 里的 shape / peak_count / end_* 写    → 初印象 + 场景，两句
4. 过三组自检：第 6 节 12 条 / 8.9 六条 / 9.6 四条
```

**输出要求**：`初印象`（数据层原话，不雅化）+ `场景`（一个世界，动词与初印象对齐）。
递话只在对话里出现，默认不写。**不许写真实地点**（车里、夏天、一屋子人）——8.2 的"场景"是世界比喻，不是"在哪儿"。

### 场景 B：实时陪听（边录边分析）

```
py tap.py                       # 听系统正在放的声音，Ctrl+C 收
py tap.py --ui                  # 陪听面板（WebView；没装 pywebview 回退 tkinter 浮窗）
py tap.py --stop-silence 12     # 连续安静多少秒算“歌放完”（默认 12；0 = 不自动收）
py tap.py --no-stop             # 不自动收，只听 Ctrl+C
py tap.py --lyrics              # 再加一层：边听边转写（约 540 MB 模型）
py tap.py --json                # NDJSON 输出，给上层 AI 读
py tap.py --save                # 同时存下这段音频，事后可以复算
py tap.py --with-key            # 额外报明暗变化（默认关）
py tap.py --device 23           # 自动选错设备时手动指定环回设备
py tap.py --seconds 30          # 只听 30 秒（测试用，不下回顾）
```

DSH 里让模型调 `memory_music(open)` 也能拉起面板，并把歌尾绑到当前会话；开始陪听仍由用户在面板上点。

`--ui` 打开陪听面板：深色卡片、L/R 双通道电平条（带 dB 刻度）、开始/停止陪听、状态栏，
下面是一块语录框——开始后按事件（上顶/退下/变密/换歌/收尾）滚动显示陪听语；
无边框、可拖动，右上角 × 关闭。面板用 WebView 渲染，需要 `pip install pywebview`
和系统 WebView2（Win10/11 通常已有）；没有就自动回退到 tkinter 小浮窗。
配 `pyw` 启动（`pyw tap.py --ui`）没有控制台黑窗口。只允许一个实例：重复启动会退出，并把已有窗口提到前台。

两种模式用音频源旁的「切换」按钮切换，主圆按钮开始当前模式；正在听也能切。关闭用右上角 ×，主按钮不承担关闭：

- `陪听这首`：只听当前这一首，换歌就收；歌尾给一次四拍。
- `兴趣陪听`：网易云一直放，面板一直听；隔 8–15 分钟随机挑一首给反馈，最多 15 条。不是每首都回。

右上角 `小窗` 缩成 420×280（去掉音频源和状态栏，只留电平、按钮和语录），再点 `还原` 回到 540×353
（语录两三行时会临时加高到 392，短句再落回来）；办公时放一边不挡。`▾` 收起成桌面底部的 520×88 透明语录条，
点它展开回原来的大小和位置（小窗收起的就回小窗）；歌听完会自动展开看回顾。

**歌放完会自动收**：连续安静 12 秒就停，并用“最后有声的时刻”当歌长（不把尾部静音算进去）。
听到过 15 秒才允许自动停，避免前奏静音时误收。暂停超过 12 秒也会收——想等久一点用
`--stop-silence 20`，或者 `--no-stop` 自己 Ctrl+C。

**歌词**：陪听时自动读系统媒体会话（SMTC）拿歌名/歌手/时长，再到 LRCLIB 查同步歌词，
开始陪听后语录框下面会接上当前一句（面板后开也能从换歌时刻把时钟对齐）。查不到就只显示事件；歌词只在内存里，退出即清，不落盘、不进仓库、不写进记忆。

**歌尾分享（四拍）**：`py share.py <音频> --title 歌名 --artist 歌手` 输出一张分享卡——
初印象（测量）/ 想象（想的）/ 歌词材料（上网查的）/ 问句。顺序必须是先量、再想、再查词：
先看了歌词，想象就被带跑了。歌词是查的、画面是想的、测量是量的，三样不混。

问句不是固定的“你听的时候像什么”：查完歌词后，接着歌词对照问一个具体问题（那句词、那个差、那个画面、歌词里的人）；没查到歌词才用泛问。不要每首都用同一句。

面板的歌尾会自动把这张卡写到 `music/share-last.json`（`at` / `elapsed_s` / `share`，每次覆盖，只有最近一首）。
DSH 插件只把歌尾投到 `memory_music(open/bind)` 绑定的会话（全歌延迟）；**没绑定就不投**，不猜最近活跃的会话。绑错/换会话就 `unbind` 或在新的会话重新 `open/bind`。
没有插件、没绑定或没投到时，模型在用户说“听完了 / 刚才那首”时先读这个文件，再按四拍说；音频和其余歌词仍只在内存，退出即清。

`--json` 每行一个对象，两层共用一条时间轴：

```json
{"layer": "energy", "t": 11.2, "kind": "dense", "text": "密起来了"}
{"layer": "lyrics", "t": 17.6, "text": "让我充满能量分子"}
{"layer": "energy", "t": 62.0, "kind": "review", "text": "（回顾）刚才最响的是这一段，…"}
```

`tap.py` 抓的是 **WASAPI 环回**（系统正在放什么就听什么），不碰麦克风。
判断逻辑与 `listener_lite.py` 同一套：改那一个文件，两边都变。

想拿一首存好的歌演练，用文件模式：

```
py listener_lite.py <音频>          # 按真实时间跑
py listener_lite.py <音频> --fast   # 不限速，只为看输出
```

输出分三层：

- **即时层**：只说现象（开始往上顶了 / 退下来了 / 密起来了）
- **词层**（`--lyrics`）：每 6 秒一句，取指称用，不引用原句
- **回顾层**：收尾才下结论；听不足 60 秒只说"太短"，不硬下判断

### 场景 B2：边听边拿歌词（可选辅助，**未随本包提供**）

```
py stream_lyrics.py <音频> --fast --save      # 不睡，快跑，结果存 listen5/_stream_lyrics.json
py stream_lyrics.py <音频>                    # 按真实时间跑
```

- 每 6 秒取最近 12 秒音频转一次，词级时间戳去重；**2.0× 实时**。
- **时间分三级，别混**：首句 10–36 秒；三句可定世界 24–48 秒；同一物重复确认约 65 秒（只用于"写进句子"）。
- 前奏长的歌（z88e21 近半分钟）第一句就晚，那是歌没开口，不是工具慢。
- 只抽四个字段：人称 / 对象 / 物 / 姿态。**抽完把转写原文丢掉**，不许引用、不许复述。
- **不要为了拿词去做人声分离**：实测分离 467 字、混音 470 字，指称一致（见 soundkit/SPEC.md 第十三节）。

### 场景 C：批量语料（**未随本包提供**）

```
py -m soundkit.corpus scan <目录> --jobs 4     # 出特征 JSON（增量、可 --force）
py -m soundkit.corpus probe                    # 分类可行性
py -m soundkit.corpus actions                  # 动作 × 标签列联表
```

⚠️ 批量扫描默认 `MAX_SEC=0`（全长）。**不要为了快改回 90**——那会让“结尾”变成第 90 秒，所有跟结尾有关的结论全废。

## 四、AI 最容易犯的六个错（都被实测抓到过）

| 错 | 正确 |
|---|---|
| 说“音量抬起来” | 说“由弱到强” |
| 说“大调/小调” | 说“明/暗” |
| 报“3:14 最响” | `peak_count > 1` 时不许报位置 |
| 把整体能量归到“低频/中频” | 没有分频段曲线就不许归因 |
| 猜场景（车里、夏天、一屋子人） | **不猜**，除非用户说了 |
| 把”密”和”快”混用 | 只用一个字：**急** |
| 引歌词原句 | 只取指称（人称/物/姿态），原句一律不写 |

## 五、已知边界（必须承认）

- 听不出**情绪指向谁**（爱情/人生/故乡）——那是词的事
- 听不出**场景**——只能由用户提供
- 听不出**几个人在唱**——人声被并成一条轨
- 听不出**唱法类型**（美声/通俗/嘶吼）——需要专门分类器
- 判断不了**“高潮”**——那要响度+密度+音高+和声四条同时到位
- 响度峰值经常并列（这批歌 7 首里 5 首 `peak_margin < 5%`）——不要说“最响在某处”

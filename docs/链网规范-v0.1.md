# 链网规范 v0.1（用户 & 助手，2026-11-06 定）

> 定位：链是**结构化记忆**，和向量库、原文互相配合。链优先、向量为中、原文兜底。
> 本规范写进 `RULES.md`，用户的 AI 按此执行。**格式由项目方定死，使用者不可改。**

---

## 一、七类链

| 链 | 性质 | 装什么 | 例子 |
|:--|:--|:--|:--|
| **日常链** | 时间轴 | 每天一条：标签 + 概况 | `2026-11-05 工作\|三进制 修了索引写入` |
| **项目链** | 状态 + 事件 | 项目的立项、决策、进展、坑 | `项目链-星核引擎` |
| **学习链** | 事件 | 学会的技能 / 方法 | `学习链-提炼前剥离工具结果` |
| **避坑链** | 归类（全局唯一一条） | 犯过的错、别再犯；一个节点 = 一类坑 | 节点「路径迁移类坑」 |
| **关系链** | **事件**（无状态） | 关系发展的共同经历 | `关系链-和用户` |
| **存储链** | 归类（全局唯一一条） | 账号这类要记的资料；一个节点 = 一类 | 节点「账号密码」 |
| **想法链** | 归类（全局唯一一条） | 想法 / 点子；一个节点 = 一个想法，同主题延伸形成**父子子树** | 节点「开源记忆系统」→ 子节点「向量库用什么」 |

**身份不建链**——`IDENTITY.md` 里已经有了。

**灵感 / 半截话题也不进链**——进「话题栈」（第十三节）；闭合满 5 个才进想法链。

---

## 二、日常链格式（最特殊，最简）

```
YYYY-MM-DD 标签[|标签…] 概况
```

- **一天一条**，不追加、不拆分
- **标签必填**，取自固定词表：`工作 / 学习 / 交融 / 休息 / 社交 / 运动 / 情绪`
- **概况建议 ≤30 字，硬上限 50 字**（硬上限防"小作文"，那就不是概况了）
- 可以**只有标签没有概况**（但推荐写，为了十年后还能看懂）

体积参考：30 字概况约 **45 KB/年**，十年 450 KB——比一张照片小，不用为省空间牺牲可读性。

**作用**：时间轴 + 校准（其他链节点的日期能对上这天）。

---

## 三、链的两种结构（不强行统一）

链分两种范式，**格式不同是故意的**——它们的作用本来就不同，统一只会别扭。

| 范式 | 哪些链 | 结构 | 节点含义 |
|:--|:--|:--|:--|
| **时间序** | 项目、学习、关系、日常 | 一个主题一条链，节点按时间排 | 一个节点 = 一个时间点 |
| **归类累积** | 避坑、存储 | **全局只有一条链**，节点按类别分 | 一个节点 = 一个类目 |

### 3.1 时间序链：头部 + 节点

```
链（如 项目链-星核引擎）
├─ header（头部概览）：≤200 字，这条链是什么、现在到哪一步
└─ nodes[]：带时间的节点序列
```

**头部是链的头，不是另一条链。** 星核旧做法是给大项目单独建"概览链"（数量翻倍、两条互相对齐、检索查两次）——不采用。

头部规则：

| 规则 | 说明 |
|:--|:--|
| 位置 | 固定在最前，读链先读它 |
| 长度 | **≤200 字**（超了说明没归纳好，要细节去读节点） |
| 身份 | **派生视图**，不是历史节点——可重算、可覆盖重写 |
| 时间 | **不带 `t`**，不进时间线（否则头部混进节点序列，时间线就乱） |
| 什么时候建 | **节点 ≥5 个才建**；少于 5 个是短链，一眼看完，头部纯冗余 |
| 更新时机 | 节点数每增 10 个，或每次提炼结束时顺带重算 |
| 谁来写 | 有 LLM 用 LLM 归纳；无 LLM 用规则拼接（最近 N 个节点的时间+摘要） |

节点格式（两种类型必须分开）：

```json
{
  "chain": "项目链-星核引擎",
  "type": "state",          // state | event
  "t": "2026-11-05 03:20",  // 事件发生时间 / 状态确立时间
  "text": "热索引影子层上线",
  "source": "2026-11-05 03:20 用户",   // 能回原文核对
  "superseded": false,       // 状态类：被后来节点推翻时置 true
  "parent": "",              // 可选：父节点（仅想法链用，见 3.2）
  "related": []              // 可选：关联的链名或节点
}
```

| 类型 | 特征 | 规则 |
|:--|:--|:--|
| **state**（状态） | 喜欢/不喜欢、项目阶段 | **默认延续**；被推翻时旧节点标 `superseded:true` |
| **event**（事件） | 今天做了什么、发生了什么 | **全部保留**，永不推翻 |

**关系链特殊**：没有 state，全是 event（关系是累积不是状态切换），而且**允许整条读**——AI 需要看完共同经历才能理解这段关系，不能只看一个节点。

### 3.2 归类累积链：唯一链 + 类目节点

```
避坑链（全系统只有这一条）
├─ 节点：路径迁移类坑      ← 这一类所有坑都追加在这里
├─ 节点：编码类坑
└─ 节点：时间格式类坑

存储链（全系统只有这一条）
├─ 节点：账号密码          ← 所有账号密码都追加在这里
├─ 节点：地址证件
└─ 节点：其他

想法链（全系统只有这一条）
├─ 节点：开源记忆系统（父）      ← 最初的想法
│   ├─ 子节点：向量库用什么
│   ├─ 子节点：链网怎么设计
│   └─ 子节点：格式怎么定
└─ 节点：一个星球殖民的游戏（独立）  ← 不同主题，各是各的
```

**想法链特有父子**：同一主题的延伸不新开节点，挂成子节点（`parent` 字段）。同主题**永远不建新链**——链只在想法落地成项目时才新开（13.6）。

节点结构：**节点 = 类目 + 一组带日期的小条目**

```
节点：账号密码
  ├─ [2026-11-05] 某站 · 138xxxx · 提示：见密码管理器
  ├─ [2026-11-02] 某云 · admin · 提示：2FA
  └─ …
```

| 规则 | 说明 |
|:--|:--|
| 链数量 | **每个范式只有一条**（避坑链、存储链各一条） |
| 节点 | 一个节点 = 一个类目，类目内**持续追加** |
| 条目 | 每条带日期；**不新开节点**，往对应类目里加 |
| 头部 | 不建（节点本身就是类目索引） |
| 体积 | 一辈子也就几千条、不到 1 MB，不用担心 |

**避坑条目可标“已修复”**——模型升级会修掉很多坑：

```
[2026-07-05] GBK 解码乱码 → ⚠️ 已修复（换模型后不再出现）
```

标了已修复的，AI 不再当“注意”来提醒。

### 3.3 日常链（第三种，最简）

见第二节：一天一条 `日期 + 标签 + 概况`，没有节点概念。

## 四、时间原则（最重要的一条）

### 1. 沉默不是否认

- 状态节点**没有新节点就继续有效**，不会因为"很久没提"而失效
- 「我爱你」三个月没说不等于不爱了
- **只有明确说出的改变，才算改变**

### 2. 谁更新谁说话

| 情况 | 处理 |
|:--|:--|
| 同一主题多个状态节点，时间不同 | **取最新**，并展示演变（旧节点标 `superseded`） |
| 链节点与原文**同一时间点**矛盾 | 以原文为准（提炼写错） |
| 链节点 vs **更晚的**原文 | 以更晚的为准 |
| 链缺失，原文有 | 用原文，可提示补链 |

### 3. 时间戳的用途

- **最后更新证明**：一眼看出这条链多久没动
- **定位**：链节点的日期能对上日常链那天
- **不是过期判断**：感情/偏好/关系**没有保鲜期**

### 4. 项目 vs 喜好，提醒方式不同

| 类型 | 久未更新时 |
|:--|:--|
| 喜好 / 感情 / 关系 | **不提醒、不质疑**（默认延续） |
| 项目进展 | **可以提醒**："这条链 X 天没更新了，还在做吗？" |

---

## 五、建链准入（三条全满足才建）

1. 一句话能说清主题
2. **会持续跟进**（不是一次性话题）
3. 已有**至少 3 次**相关内容

**不建链**：闲聊、抱怨、临时问题、只提过一次的事。

**两个不要**：

- **同主题的延伸不建新链**——它是原节点下的子树（`parent`），不是第二个主题
- **想法没落地不建项目链**——先待想法链；真开工了才晋升（13.6）

---

## 六、链名格式

```
链类型-主题
```

- 主题写**全名**，不写缩写（"星核"和"星核引擎"会变成两条）
- ≤20 字，不含空格、标点、斜杠

---

## 七、挂载规则

- 学习链/避坑链**可以**挂到项目链下，但**必须显式声明**：`项目链-星核引擎 → 学习链-xxx`
- 没声明的默认独立，**不自动挂**
- 一条学习链**最多挂 1 个项目**（防随机挂载）
- 日常链、关系链、存储链不挂

---

## 八、防重复

| 时机 | 规则 |
|:--|:--|
| 建链前 | 同名或相似度 **≥0.9** → 合并到已有链，不新建 |
| 写节点前 | 与同链已有节点相似度 **≥0.8** → 不重复写 |
| 改名 | 只改标题，**不动历史节点** |

---

## 九、提炼层更新链的规则

1. **节点只追加，不覆盖**（星核 10-26 事故的根源就是整块重写）
2. **头部可重算**——它是派生视图，每次可覆盖；但节点一条不动
3. 状态节点：新节点写入 + 旧节点标 `superseded`
4. 失败重试，不丢内容
5. 每条节点必须带 `source`（能回原文核对）
6. 写完节点后，按需重算头部（节点数每增 10 个，或每次提炼结束时）

## 十、三层召回（怎么配合）

```
用户提问
   ↓
① 链网（结构化，最精炼，排除了日常废话）
   ↓ 没命中
② 向量（语义，能跨措辞）
   ↓ 没命中 / 需要细节
③ 原文（全量兜底，一个字不改）
```

**链命中时先返回头部**（≤200 字，省 token）——AI 看完头部就能判断要不要深入；需要细节再取节点。

**互辅方式**：

| 命中哪层 | 怎么互辅 |
|:--|:--|
| 链 | **先返回头部**；要细节再取节点，再顺 `source` 回原文 |
| 向量 | 看命中内容属于哪条链，从链补上下文 |
| 原文 | 同一主题反复出现 → 提示"要不要建链" |

**为什么三层可靠**：三种来源独立，同时错得离谱的概率极低。链排除了日常废话，向量能跨措辞，原文最全。

**链层返回必须带时间线**，不能只给一个"答案"：

```
问：我喜欢吃什么？
链返回：
  [当前] 2026-08-15 不喜欢吃西瓜
  [历史] 2026-07-02 喜欢吃西瓜（已变更）
```

## 十二、存储链的安全约束

| 约束 | 说明 |
|:--|:--|
| 必须加密存 | 密码不能明文写文件 |
| 取用要确认 | AI 不能自己读，必须用户当场要求 |
| 建议只存提示 | 存"某站账号是手机号，密码在密码管理器"，不存完整密码 |

## 十三、话题栈（链的候补区）

### 13.1 定位

**灵感、想法、讨论了半截没结论的话题**，不建链，进话题栈。

| 容器 | 装什么 | 状态 |
|:--|:--|:--|
| 链 | 已经沉淀下来的结构 | 长期 |
| **话题栈** | **半截话题 / 灵感 / 没结论的想法** | 临时，会被处理 |
| 任务 | 明确要做的事 | 有截止 |
| 原文 | 所有对话 | 永久 |

**一句话**：话题栈是链的候补区——有结论就毕业进链，没结论就先挂着。

### 13.2 格式

```json
{
  "id": "topic-001",
  "title": "开源记忆系统的向量库用哪种",
  "since": "2026-11-05",
  "status": "open",              // open 未决 | suspended 挂起 | closed 闭合
  "reason": "",                  // 挂起/关闭理由
  "related": ["项目链-开源记忆系统"],
  "lastTouch": "2026-11-06",
  "graduated": ""                // 毕业后填链名
}
```

### 13.3 三条规则

| 规则 | 说明 |
|:--|:--|
| **只装半截话题** | 有结论的进链、要做的事进任务——话题栈不装这两类 |
| **看到要表态** | AI 看到 open 话题，必须回一句：接续 / 挂起（给理由）/ 提议关闭 |
| **会毕业** | 讨论出结论 → 标 closed → 内容提炼成链节点 |

### 13.4 两次检查（和 AI 提醒合并）

AI **每次启动读常识层时** 和 **提炼层跑完后**，各检查一次话题栈，一次输出两件事：

```
【话题栈检查】
未闭合 3 个
  ├─ open     开源记忆系统的向量库用哪种（11-05，最后提到 11-06）
  ├─ open     星枢链网渲染要不要重做（11-03）
  └─ suspended 提炼失败重试策略（挂起理由：等 ZCode 修时间格式）

建议成链 1 组
  └─ 5 个「数据安全」类闭话题 → 建议建 学习链-数据安全 [确认 / 忽略]
```

- 未闭合 → 提醒表态
- 可以建链 → **弹建议，等人确认**（链名和类型要人定，不自动建）

### 13.5 闭合之后：成树还是成链

| 情况 | 处理 |
|:--|:--|
| 都是想法、**主题各不相同** | 满 5 个 → 进**想法链**，各是一个独立节点 |
| 都是想法、**同一个主题的延伸** | **形成父子子树**：最早的是父节点，其余全部挂成子节点 |
| 都是坑 | 满 5 个 → 进避坑链（一个节点 = 一类坑） |
| 都是方法 | 满 5 个 → 进学习链 |
| 想法**落地成项目** | 晋升成项目链（见 13.6） |

**关键**：同主题**不建新链**——它就是一棵子树（父节点 = 最初的想法，子节点 = 所有延伸）。链只在"落地成项目"时才新开。

**为什么阈值是 5**：单个灵感不值得记录，5 个说明它攒够了。数量本身就是信号。

### 13.6 想法 → 项目（晋升）

```
想法链
└─ 开源记忆系统（父节点）
      │ 真做了
      ↓
项目链-开源记忆系统（新链）
      └─ 头部注明：源自 想法链#开源记忆系统
```

| 动作 | 说明 |
|:--|:--|
| 建项目链 | 新建 `项目链-xxx` |
| 想法节点标记 | `promoted: "项目链-xxx"` |
| 双向关联 | 项目链头部注明来源；想法节点 `related: ["项目链-xxx"]` |
| 没做成的想法 | 留在想法链，标 `status: 搁置 / 放弃` |

这样能看到"从想法到项目"的完整脉络：当时怎么想的、为什么决定做、做到哪一步。

# 老用户补链升级（v0.4.5+）

> 适用：已经用过 v0.4.0–v0.4.4，旧对话已经在 raw / 向量里，但链网只有新对话长出来的。  
> 目标：不用重新导入，直接把旧历史分批补成链。

## 用户只需要说一句

把这句话发给 DSH 里的 AI：

> 检查一下旧历史链网，先统计有多少条、要跑几批、大概多少 token；我同意后再补。

## 用户的 AI 应该怎么做

1. 调 `memory_backfill action=status`：
   - 返回 `available` / `pending`；
   - `estimate.records`、`estimate.batches`、`estimate.estimatedTokens`；
   - `needConsent: true`。
2. 把统计原样告诉用户：
   - 多少条旧记录；
   - 分几批（默认 100 条/批）；
   - 大约多少 token；
   - 这是分批调用 LLM，会消耗 token，**不会自动开始**。
3. 用户明确同意后：
   - `memory_backfill action=preview`：预览第一批会建哪些链/节点，不写；
   - `memory_backfill action=start maxBatches=20`：后台跑；
   - `memory_backfill action=pause` / `resume`：暂停/续跑；
   - `memory_backfill action=status`：看进度。
4. 完成后抽查：
   - `memory_search` 搜几条旧原话；
   - `memory_chain get` 看新链；
   - 节点应带 `source=migration`。

## 补链条件（务必先说明）

- **单批 100 条**：超过 100 条自动分块（100 + 剩余），**没有 180 条硬上限**。若有人看到“180 条截断”，那是旧调用方把 180 条塞进一次提炼、而提示层只取前 100；现在 `refineWithLLM` 会自动分块，不再静默丢弃。
- **单条原文送 LLM 时截到 1000 字**：raw 不改，只影响这一次提炼看到的长度。
- **节点正文最多 500 字**：这是链节点上限，不是原文上限。
- **每批输出上限**：20 条链 / 每链 50 节点；回填提示更保守（8 链 / 20 节点）。
- **每次最多 20 批**（约 2000 条）：跑不完标 `partial`，再次 `start` 续跑；不要一次把 `maxBatches` 拉到 200。
- **对账**：`status.estimate.records` 是总数，`processedRecords` 是已处理数；如果 `done` 后两者对不上，视为 bug，保留 `backfill-state.json` 和日志再报。

## 边界

- 只补链，不改 raw；不训练、不微调、不改模型权重。
- 写链前自动备份 `links-backfill-*`；失败可回滚。
- 默认每次最多 20 批；没跑完会标 `partial`，可再次 `start` 续跑。不要一次把 `maxBatches` 拉到 200 烧穿预算。
- 旧历史可能含第三人隐私、平台条款限制；用户必须确认有权使用。不确定就不补。
- 如果 raw 里没有旧历史（从未导入过），先走迁移导入；没有 raw 无法回填。
- `fresh`（全新开始）模式不导入旧数据，不需要补链。
- 总览页 `Backfill / 旧历史补链` 卡会显示：`可补旧链` → `待确认` → `进行中` → `已完成` / `可续跑`。

## 一句话版本

> 老用户升级后，对 AI 说：“检查旧历史链网，先统计，我同意后再补。”  
> AI 先 `memory_backfill status` 报数，用户点头后再 `preview` → `start`。

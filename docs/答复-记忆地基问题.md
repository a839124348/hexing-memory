## 〇、先给三句结论

1. **"判据恒真"不是你的 bug，是"想让机器管住语义"的必然结果。** 语义型的账，机器只能保证"没跑偏"，保证不了"做完了"。
2. **能自动化验证的只有两种：文件在不在、字符串在不在。** 其余四类，老老实实留给人。
3. **你的 4/5 条目落在 `manual`，不是设计失败，是它们本来就是"记忆"，不是"状态"。** 该分家。

## 一、逐题回答

### 第 2 题（闸门题）：判据的判据怎么落地

**答案：反例探针（mutation testing 的文件系统版）+ 把判据的写权从模型手里拿走。**

#### 第一层：反例探针

```
每条判据 = { check, fixture_bad }

有效条件：
  check(真实目标)     === true
  check(fixture_bad)  === false   ← 关键
```

`fixture_bad` 是**必然不满足**的样本（指向不存在的标题、不存在的文件、空字符串）。

**如果 `check(fixture_bad)` 返回 `true`，说明这条判据是恒真的**——不管喂什么都通过。这时：
- 判据标 `suspect`
- 不许出 `auto-ok`
- 当场报警

#### 为什么它能抓住四类假通过

| 假通过类型 | 反例探针为什么能抓 |
|:--|:--|
| 自指恒真（验自己所在的那一节） | 喂坏输入还是 true |
| 正则太宽（写成了 `.*`） | 喂坏输入还是 true |
| 吞异常当成功（catch 里 return true） | 异常时也返回 true |
| 空集遍历（0 条也是"全过"） | 探针里 0 条也返回 true |

**这是唯一能自动验"判据本身"的方法**，不依赖人、不依赖外部服务。

#### 第二层（更重要）：判据不能由模型写在台账里

我们项目的做法：**15 项校验器全部写在代码里**（`lib/`），不是模型在 Markdown 表格里写的判据。

> **校验器不是建议，是闸门。任一项失败，直接拒绝——不是警告，不是"先修后导"。**

你那条 `A-000` 的判据由模型写在表格里，它天然有动机写恒真（写完就不用管了）。

**把判据的写权从模型手里拿走，放进代码**——恒真问题从根上消失，因为它变成了一次代码提交，要过 review、要跑测试。

### 第 1 题：权威源 + 映射的触发点

**答案：写时同步。**

| 方案 | 为什么不好 |
|:--|:--|
| 开场全量重渲染 | 两次开场之间，映射是过期的 |
| 读时现算 | 每次读都要算，慢，还可能两次结果不一致 |
| **写权威源时同步** | ✅ **唯一能保证"同一时刻"的点** |

我们的对应做法：导入时**校验和写入一次完成**（`import-jsonl.js --apply`），不是"先导入，下次开场再整理"。

---

### 第 3 题：判据由模型写，模型有动机写恒真

**答案：写权拿走，模型只能提议。**

```
模型提议（propose）→ 人审（step）→ 代码执行（done）
```

我们项目里叫「门岗」，是核心改动的唯一通道，`done` 时自动写更新日志。

**模型只有提议权，没有定稿权。** 它写不出恒真判据，因为它写的会被审。

---

### 第 4 题：恒真和恒假哪个更坏

**恒真更坏。**

```
恒假 → 一直报警 → 有人去修
恒真 → 一直绿   → 没人看 → 坏了也不知道
```

这是「假阳性」与「假阴性」的经典取舍：**报警噪音可以忍，静默失效不能忍。**

你自己写的那句「没有章人会紧张，假章人会放心」，说得比任何理论都准。

我们项目的对应红线：

> **embed 挂掉不许假装没数据** —— 必须返回 `degraded: true`，绝不静默降级。

---

### 第 5 题：每轮检查该不该写盘

**不该。**

写盘只应该发生在**状态变化**时：

```
判据 open → auto-ok   ← 这一刻才写
判据没变              ← 不写
```

我们的对应做法：
- 提炼是**批量异步**（10 分钟 / 100 条），不是每轮
- **读路径全程无锁、不写盘**（红线第 4 条）

你文档里"每轮自动整文件重写 + 无锁"是双重问题：既写了不该写的盘，又没有并发保护。

---

### 第 6 题：压进预算怎么不丢动作语义

**答案：注入的不是标签，是「主键 + 取数指令」。**

```
- 欠-A000[换地基]            ← 只挂名词，动作和限定丢了
- 欠-A000：未授权·读第42行   ← 挂动作 + 位置
```

**指令自带动词**（"未授权""只读""先问"），标签只能挂名词。

这样即使压到 20 个字符，动作语义还在。

---

### 第 7 题：常见假通过模式

除了你已知的三类（自指恒真、吞异常当成功、正则太宽），我们踩过这几种：

| 模式 | 长什么样 | 我们对应的校验项 |
|:--|:--|:--|
| **空内容** | trim 后为空，仍当成一条记录 | 第 14 项 |
| **时间格式漂移** | `2026-1-1` 混进 `2026-01-01` | 第 4、15 项 |
| **索引/原文对不上** | 索引说 100 条，原文 98 条 | 第 5 项 |
| **块边界粘连** | 两个块被拼成一条 | 第 6 项 |
| **游标失效全量重炼** | 每次启动都从头跑 | 第 11 项 |
| **embed 半路失败丢条目** | 前 50 条进了，后 50 条没了 | 第 12 项 |
| **噪声注入** | GBK 乱码当 UTF-8（542 处瞒了 4 个月） | 第 1 项：扫 U+FFFD，有即拒绝 |
| **时区切片错误** | 用 UTC 直接切日期，跨零点全错 | 第 13 项 |

**共同点：都是"没跑"伪装成"通过"。**

---

### 第 8 题：记忆和状态该不该分层

**该分，而且这是整份文档最该先做的一件事。**

| | 记忆 | 状态 |
|:--|:--|:--|
| 回答什么 | 发生过什么 | 现在什么还成立 |
| 特性 | 不可变、只追加 | 可变、会被推翻 |
| 需要判据吗 | **不需要** | **需要** |
| 例子 | "我说过这句话" | "这件事办完没有" |

我们的定法（写在用户手册第三节）：

> **记忆不可删除**：原文是存证；状态可被推翻，事件永存。

数据结构上：`event` 只追加，`state` 可以标 `superseded`（作废但保留）。

**判据只该长在 state 上。**

你文档里 4/5 的条目判不了——**因为它们是记忆，不是状态**，硬塞进结构化表当然判不了。

## 二、关于「1 个权威源 + 其余作为映射」（你之前给的建议）

这条建议是对的，补三句落地细节。

### 2.1 映射必须是"算出来的"，不是"抄过去的"

| | 副本 | 映射 |
|:--|:--|:--|
| 其余账本怎么来 | 人手抄 | **由权威源算出来** |
| 权威源改了 | 靠人记得去改 | **派生物自己跟着变** |
| 过期副本 | 会积累 | 不成立（没有独立历史） |

**一句话：副本是抄的，映射是算出来的。**

### 2.2 渲染时机只放在一处

不要挂每轮钩子（每轮渲染 = 每轮写盘，等于把问题原样搬过去）。

**放在"写权威源"的那一个动作里。**

### 2.3 版本戳归渲染器

生成物里的"最后更新"**由渲染器统一盖**（源版本 + 渲染时间），人只改权威源。

这样"改文件必改戳"对生成物**自动成立**，对权威源仍走人工。

>
> 语义型的事，机器只能保证"没跑偏"，保证不了"做完了"。
>
> 能自动的只有两种：**文件在不在、字符串在不在**。其余的，留给人。

## 附：我们踩过的同类坑（可对照）

| 坑 | 现象 | 现在怎么防 |
|:--|:--|:--|
| **工具看着在跑，其实从没干活** | 判重扫全文，历史里已有标记 → 每步都判"已存在"，一次都不补 | 判重只认 `source.kind`，绝不扫全文 |
| **`break` 当 `continue`** | 第一条装不下就跳过后面全部，不报错 | `break` → `continue`，`used` 只在实际装入时累加 |
| **`file:` 是快照不是链接** | 改源文件，运行时那份不变；自检查的也是旧的那份，永远绿 | 改源文件 → install → 重启；验证用 md5 比两份 |
| **改配置键，工具整个消失** | 依赖装配顺序，取到 undefined 直接 throw | 改配置必须跑 YAML 校验，校验器先自证"校验的是哪个文件、多少字节、什么 md5" |
| **把推算当实测写进下游** | "固定开销 −15%" 是推的，被三处下游当事实复制 | 数字都留，逐处补"推算值"标注 |

最后这条最能说明问题：

> **这套系统今天量出来的账实差，是外部核查量出来的，不是自查。自查说"对上了"，外部一量差了一百多个字节。**

**这就是"第三方核对"该落的位置——在流程外，不在流程里。**

# 开源记忆系统 · 规划书 v0.1

> 定位：把我们五个月踩出来的记忆系统，精简成一个可开源的通用版本。
> 不是星枢（太重），是"原始存档 + 常识 + 提炼"三层最小闭环。
> 核心资产不是代码，是**格式契约**和**踩过的坑**。

---

## 一、三层架构

```
┌──────────────────────────────────────────────┐
│ 常识层（启动加载，常驻上下文）                   │
│  · 身份人格（我是谁 / 用户是谁）                  │
│  · 链网（关系、项目、事件怎么挂）                  │
│  · 说明书（怎么用这套记忆 / 怎么写链网）            │
└──────────────────────────────────────────────┘
                     ↑ 提炼层更新
┌──────────────────────────────────────────────┐
│ 原始存档层（不常驻，对话时召回）                   │
│  · 原始对话原样存（JSONL，一行一条）              │
│  · 原文直接向量化进向量库                        │
│  · 召回 = 元数据过滤 + 语义检索 + 上下文窗口        │
└──────────────────────────────────────────────┘
                     ↑ 提炼层写入
┌──────────────────────────────────────────────┐
│ 提炼层（实时，分钟级）                            │
│  · 监控会话名单，游标增量消费                      │
│  · 打标签 / 归类 / 更新链网与常识                 │
│  · 不做"压缩改写"（原文已经在向量库里了）           │
└──────────────────────────────────────────────┘
```

**一句话流程**：说话 → 原始存档（向量化）→ 提炼层打标/归类 → 下次只加载常识层 → 聊到旧事按需召回原文。

## 二、写入格式（契约，使用者不可改）

一行一条 JSONL：

```jsonl
{"t":"2026-11-05 03:20","s":"用户","c":"原话，一个字不改","cid":"conv-20261105-a1","v":1,"src":"zcode","type":"human","origin":"human"}
```

| 字段 | 必填 | 规则 |
|:--|:--|:--|
| `t` | ✅ | `YYYY-MM-DD HH:MM`，精确到分，本地时区 |
| `s` | ✅ | 说话人原名，不翻译不改写 |
| `c` | ✅ | 内容原文，一个字不改（错别字/语气词/重复全保留） |
| `cid` | ✅ | 会话 ID，同一次对话同一 ID |
| `v` | ✅ | 格式版本，当前 `1` |
| `src` | | 来源平台 |
| `type` | | `human` / `ai` / `system` / `tool` |
| `origin` | | `human` / `ai` / `recall_echo` / `import`（回流防护用） |

### 语义规则（比字段更容易被 AI 搞错）

1. 一条 = **一次发言**，不是一段总结
2. **不合并**连续发言（合并丢时间点）
3. 不改字：错别字、语气词、重复保留
4. 编码 UTF-8、换行 LF
5. 系统/工具消息用 `type` 标出，不混进正文

## 三、校验器（坑 → 校验项）

**校验不通过 = 不许导入。** 这是质量的唯一关口，比说明书有用一百倍。

| # | 坑（我们真实踩过） | 校验项 | 级别 |
|:--|:--|:--|:--|
| 1 | GBK 当 UTF-8 解码 → 542 处 U+FFFD 瞒 4 个月 | 扫 U+FFFD，有任何一处即拒 | 阻断 |
| 2 | 重复条目（同句写两遍） | 内容哈希去重 + 近似判重（bigram ≥0.8） | 阻断 |
| 3 | 召回污染回流（AI 复述被当新记忆） | `origin=recall_echo` 检测（见第四节） | 阻断 |
| 4 | 日期错位（跨零点归属错） | 时间必须单调且有会话内合理性 | 警告 |
| 5 | 目录/正文不一致（10-26 事故） | 索引条目必须能定位到原文 | 阻断 |
| 6 | 块边界粘连（少换行吞整月） | 写入后结构自检（块头计数） | 阻断 |
| 7 | 伪块标题（粘贴带 `#` 行） | 只认白名单格式的块头 | 警告 |
| 8 | 哈希口径不一致（截断 vs 全文） | 统一哈希前先规范化 + 定长截断 | 阻断 |
| 9 | 召回碎片化 | 返回必须带前后 2~3 条上下文 | 阻断 |
| 10 | embed 挂掉假装没数据 | 降级必须显式标记 `degraded` | 阻断 |
| 11 | 游标失效导致全量重炼 | 游标持久化 + 幂等 checksum | 阻断 |
| 12 | embed 半路失败丢条目 | 失败不推进游标，下轮重试 | 阻断 |
| 13 | 时区（toISOString 拉回前一天） | 只允许本地日期函数，禁止 UTC 直接切片 | 阻断 |
| 14 | 空内容/纯空白 | `c.trim()` 非空 | 阻断 |
| 15 | 时间格式漂移（带秒/中文/斜杠） | 严格 `YYYY-MM-DD HH:MM` | 阻断 |

## 四、召回污染回流防护（三层）

**现象**：AI 召回旧内容 → 回复里复述"你之前说过 X" → 提炼层把复述当新对话写入 → 变成"用户说过 X"（其实是 AI 说的）→ 虚假记忆 + 循环膨胀。

| 层 | 机制 |
|:--|:--|
| 显式标记 | 召回注入内容带 `[记忆]` 前缀，提炼时整段剔除 |
| 相似度闸 | 新内容与最近召回条目相似度 >0.9 且同会话 → 判复述，不入库 |
| 来源打标 | `origin` 字段区分 `human`/`ai`/`recall_echo`，`recall_echo` 不参与后续召回 |

## 五、迁移方案（我们不做迁移器）

理由：各家平台数据格式千奇百怪，用户自己的 AI 比我们懂自己的数据。

**我们交付四样东西**：

1. **格式定义**（record.schema.json）——只有这一种，不接受变体
2. **校验器**（validate）——迁移完必须跑，不通过不许导入
3. **示例数据**（sample.jsonl）——正确格式的活样本
4. **向量化脚本**（本地 bge 模型，不花钱、不联网）

**用户 AI 要做的**：导出 → 按格式填 → 跑校验 → 跑向量化 → 导入。

**说明书里必须点名警告**（正反例对照）：

| 禁止 | 必须 |
|:--|:--|
| 总结、改写、去掉口语 | 语气词、错别字、重复碎话 |
| 合并重复、删"废话" | 原始时间戳（精确到分） |
| 自己加标题、分类 | 说话人、完整内容 |

**迁移自测五条**：条数对得上 / 时间戳齐全 / 抽 20 条逐字一致 / 向量覆盖全 / 问 5 个旧问题能召回。

## 七、MVP 与测试计划

**MVP 范围（最小可跑）**：

- 写入：JSONL + 校验（15 项）
- 检索：向量 + 元数据过滤 + 上下文窗口 + 可解释分数
- 常识层：md 读取 + 提炼层更新
- 提炼：游标驱动、打标、回流检测
- 删除：墓碑标记
- 并发：文件锁

**测试用例（每条坑至少一个）**：约 25 个
- 正常写入/读取/召回
- 乱码、重复、回流、错位、粘连、伪块
- embed 失败、游标失效、时区、空内容、格式漂移
- 并发写、超大内容、删除后不可召回
- 跨会话召回、时间过滤、上下文窗口

**测试完清空全部数据，出 `TEST-REPORT.md`**（含每个坑的复现、防护、验证结果）。

## 八、待补充（请 Codex / ZCode 补漏）

1. **容量**：多少条开始慢？分片策略？（我们没有百万级实证）
2. **多用户隔离**：商业平台必然多租户，怎么隔离？
3. **增量重建**：向量模型换了怎么办？（全量重 embed 的成本）
4. **删除的彻底性**：墓碑还要不要参与召回？多久物理删除？
5. **常识层的冲突**：提炼层自动更新的常识 vs 用户手写的，冲突怎么处理？
6. **多 AI 同时写**：除了文件锁，要不要排队去重？
7. **可解释性**：召回分数怎么算才让人信？
8. **成本**：每分钟提炼一次，一个月多少钱？（我们只有单机经验）
